# 服务器基础

## 服务器是什么

服务器是网络中为其他设备（客户端）提供计算、存储、数据、应用等服务的计算机系统或软件程序。它通常需要 7×24 小时运行，强调高性能、高可靠、高并发、可扩展和易管理。硬件上常见多核 CPU、大容量内存、硬盘/SSD、RAID、冗余电源和高速网卡；软件上运行 Windows Server、Linux 等操作系统，以及 Web、数据库、文件、邮件、云平台等服务。常见形态包括塔式、机架式、刀片、云服务器和边缘服务器。与普通电脑相比，服务器更重视稳定、安全、远程管理和持续服务能力。

## 公网、私网与内网穿透

- **实验室服务器**：在内网里，只有私网 IP，外面进不来。
- **云服务器**：在公网，有公网 IP，外面能找到它。

【以下为摘抄】

FRP（Fast Reverse Proxy）开源、跨平台的**反向代理内网穿透工具**，作者 fatedier，Go语言编写。

> 核心思想：**内网机器主动出站，和公网中转服务器建立长连接隧道；外网流量走公网服务器，再通过这条已经存在的隧道转发回内网**。

它**没有真正把内网主机变成公网主机**，只是流量中转。

FRP分为两个独立程序：

  1. **frps（frp server，服务端）**：部署在**带公网IP的云服务器**上。监听端口，等待frpc来连接，接收外网用户请求，做流量转发。
  2. **frpc（frp client，客户端）**：部署在**内网机器（你的实验室服务器）**。主动发起连接到frps，注册要暴露的本地服务，接收隧道里转发来的流量，再发给本机上跑的服务（ssh、jupyter、web等）。

> ⚠️重点：**连接是frpc主动向外发起**。校园网/实验室NAT防火墙一般放行【内网向外发起的连接】，但拒绝【外网主动向内发起连接】。这就是frp能穿透的根本原因。

### 完整工作流程

  1. **启动frps（云服务器）**

云服务器上运行frps，监听一个控制端口（默认7000），读取配置，等待frpc接入。

  2. **启动frpc（实验室服务器）**

frpc读取frpc配置：frps的公网IP、token认证、代理规则（比如：把本地`127.0.0.1:22`ssh，映射到云服务器`0.0.0.0:60022`）

frpc主动发起TCP连接 → 连上frps。

连接建立、token校验通过后，frpc**向frps注册代理信息**，并维持一条**控制长连接**（心跳保活，断了会自动重连）。

> 控制连接：用来传递指令（通知新用户来了、建立数据通道），不是业务数据流。

  3. **外部用户发起访问**

外部电脑执行 `ssh 云服务器IP -p 60022`

    - 请求到达云服务器上frps监听的60022端口；
    - frps查到：这个端口属于刚才注册的ssh代理；
    - frps 通过**控制连接**通知frpc：来了一个新连接，请准备接收数据；
    - frpc新建一条**数据隧道连接**，frps把外部ssh流量丢进隧道；
    - frpc收到隧道流量 → 转发给实验室本机 `127.0.0.1:22` 的ssh服务；
    - 实验室ssh服务返回响应数据 → 原路：frpc →隧道→frps→外网用户。

> 多路复用（默认开启）：多个用户请求**复用同一条长连接隧道**，不用每来一个访问就新建一条TCP，减少握手开销、节省文件句柄，提升并发性能。

### 代理类型

  - `tcp`：原始TCP端口映射，SSH、数据库、jupyter 最常用，就是上面例子；
  - `udp`：UDP流量转发，比如DNS；
  - `http / https`：域名方式，不需要占用云服务器大量端口，可以端口复用，绑定域名；
  - `stcp`（安全tcp）：**不在frps上开放端口**。外部访问者也跑frpc，双方通过frps握手。只有知道密钥的人才能访问，公网没有暴露端口，安全性更高；
  - `xtcp`（P2P，点对点）：frps只做握手。握手成功之后，**数据直接两端互通，流量不再经过云服务器中转**，带宽不受云服务器限制；如果打洞失败，自动降级成frps中转模式。

### 关键特性

  1. **认证**：token，frpc和frps必须一致，防止别人随便连你的frps；还支持tls加密隧道流量；
  2. **压缩**：开启transport压缩，减少带宽；
  3. **端口复用**：多个http代理可以共用云服务器同一个80/443端口，靠Host域名区分；
  4. **连接池**：预建立一批隧道连接，新请求来时直接取用，省去新建连接延迟，适合高并发短连接场景；
  5. **web面板**：frps自带dashboard，看在线客户端、代理状态、流量统计。

### 局限与风险

  1. **所有中转流量都走云服务器**。你的ssh/jupyter的流量会经过云主机，带宽上限=云服务器带宽。xtcp打洞成功才不走云机。
  2. **安全风险**：一旦把端口暴露到公网，会被爬虫、爆破脚本扫描（ssh端口尤其危险！）。

推荐做法：

    - 尽量使用stcp而不是tcp；
    - ssh不要用弱密码，最好密钥登录；
    - 云服务器防火墙只放行必要端口；
    - 开启tls加密隧道，token足够复杂；
  3. **心跳断连**：校园网NAT有超时，如果长时间没有流量，NAT会把长连接踢掉。frpc自带心跳，会自动重连，但短时间会掉线；
  4. **IP溯源**：在实验室服务器上看到的连接来源IP，**是云服务器内网IP，不是真实外网访问者IP**；因为流量是frps转发过来的。如果你要拿到真实访客IP，http场景可以配置透传header，TCP无法原生透传源IP。

## 存储位置

- **用户盘**：相当于个人电脑的 C 盘，有配额。
- **数据盘**：挂载在机械盘上，空间更大，适合放数据集。
- **共享数据盘**：方便同做一项工作的成员共用数据集。

| **内容** | **放哪里** | **原因** |
| --- | --- | --- |
| 代码 | 用户盘 | 执行更快 |
| 参数、预训练参数 | 数据盘 | 不占用户盘配额 |
| 数据集 | 数据盘或共享数据盘 | 空间大，方便共享 |
| 个人临时文件 | 用户盘自己的目录 | 自己管理 |
| 大型数据集 | 专用数据集目录 | 防止服务器崩溃 |

**不要用用户盘长期存放数据。**

## 权限边界

实验室服务器是多人共用的。**只动自己的文件、环境和进程；要动系统或别人的内容，先找管理员。**

### 最基本的权限

`ls -l` 最左边会出现类似 `drwxr-xr-x` 的字符：

- 第一个字符表示类型：`d` 是目录，`-` 是普通文件。
- 后面九个字符分成三组，依次表示**文件主人、同组用户、其他人**。
- `r` 是读取，`w` 是修改，`x` 是执行，`-` 是没有该权限。

| 数字权限 | 含义 | 常见用途 |
| --- | --- | --- |
| `755` | 主人可读写执行，其他人可读和执行 | 脚本、程序目录 |
| `644` | 主人可读写，其他人只读 | 普通文件、配置文件 |
| `600` | 只有主人可读写 | 私钥、敏感文件 |
| `700` | 只有主人可读写执行 | `.ssh` 目录 |

`chmod` 用来修改权限，例如 `chmod 755 script.sh`。

`chown` 用来修改文件主人，普通用户通常不能随便使用。

### 什么可以自己做

- 管理自己目录里的文件，上传或删除自己的数据。
- 创建自己的 Conda 环境，在环境里安装 Python 包。
- 用 tmux 运行自己的任务。
- 用 `top`、`nvidia-smi`、`df -h` 查看资源。
- 修改自己的脚本和配置，并及时备份重要数据。

### 什么需要找管理员

- 安装系统级软件、使用 `sudo` 或 `apt`。
- 修改系统配置、CUDA、驱动或共享目录权限。
- 使用 Docker，或需要特殊权限。
- 磁盘空间不足、服务器无法连接或出现异常进程。
- 别人的进程占用资源，或需要一次使用全部 GPU。

> **不要做：**滥用 `chmod 777`、随便使用 `sudo`、修改别人的文件、杀死别人的进程、共享账号或私钥。
> 核心原则：自己的事情自己处理；涉及系统、共享资源或其他用户，先问管理员。

## 使用红线

| 红线 | 简单说明 |
| --- | --- |
| 不长期占用 GPU | 任务结束就释放；程序卡死时，只结束自己的进程。 |
| 不运行来源不明的项目 | 陌生代码可能包含木马、挖矿程序或攻击脚本。 |
| 不在公共电脑登录 | 密码和私钥可能被记录；私钥只保存在自己的设备上。 |
| 不转借服务器 | 账号和密钥只能本人使用，别人的操作也会记在你的账号下。 |
| 离开前备份和清理 | 服务器空间有限，长期不用的账号和文件可能被清理。 |

### 离开服务器前检查

- [ ] **程序状态**：程序还需要继续运行吗？
- [ ] **数据保存**：结果、日志和中间文件已经保存了吗？
- [ ] **GPU 使用**：不用的进程已经结束了吗？
- [ ] **磁盘空间**：临时文件需要清理吗？
- [ ] **后台会话**：tmux/screen 应该保留还是关闭？
